# API reference

Interactive OpenAPI docs are generated by FastAPI: **http://localhost:8000/docs** (Swagger UI) and `/redoc`. The VS Code REST Client file [`api.http`](../api.http) contains ready-to-send requests.

## Conventions

| Item | Convention |
|---|---|
| Prefix | `/api/v1` |
| Format | JSON; uploads use `multipart/form-data` |
| Time | ISO 8601, always UTC (`2026-11-03T09:30:05.319577Z`) |
| Pagination | `page` (1-based), `page_size` (1–200); responses `{items, total, page, page_size, pages}` |
| Errors | `{"error_code": "...", "message": "...", "details": ...}` with 400 / 403 / 404 / 409 / 413 / 422 / 429 / 500 |

## Endpoints

| Method | Path | Purpose | Writes |
|---|---|---|---|
| GET | `/health` | Liveness + DB check (503 if DB down) | |
| GET | `/api/v1/config` | `read_only`, upload limits for the UI | |
| GET | `/api/v1/datasets` | List datasets with processing stats and alert counts | |
| POST | `/api/v1/datasets/upload` | Upload & process a file (`file`, `source_type`=`NGINX\|SSH\|AUTO`, optional `name`) | ✔ |
| GET | `/api/v1/datasets/samples` | Available synthetic samples | |
| POST | `/api/v1/datasets/samples/{key}` | Import a sample | ✔ |
| GET | `/api/v1/datasets/{id}` | Detail + error summary + first 200 import errors | |
| POST | `/api/v1/datasets/{id}/detect` | Re-run detection (idempotent) | ✔ |
| DELETE | `/api/v1/datasets/{id}` | Delete dataset and everything linked to it | ✔ |
| GET | `/api/v1/events` | Filter: `dataset_id, source_ip, source_type, status_code, start, end, q` | |
| GET | `/api/v1/events/{id}` | Raw line, normalised fields, linked alert IDs | |
| GET | `/api/v1/alerts` | Filter: `dataset_id, severity, status, source_ip, rule_code` | |
| GET | `/api/v1/alerts/{id}` | Explanation, rule, evidence (≤ 500), notes | |
| PATCH | `/api/v1/alerts/{id}/status` | `{"status": "OPEN\|ACKNOWLEDGED\|RESOLVED"}` | ✔ |
| POST | `/api/v1/alerts/{id}/notes` | `{"note": "..."}` (1–5000 chars) | ✔ |
| GET | `/api/v1/rules` | Rule definitions, thresholds, windows, versions | |
| GET | `/api/v1/dashboard/summary` | All dashboard aggregates; optional `dataset_id` | |
| GET | `/api/v1/exports/events.csv` | Same filters as `/events`; streamed CSV | |
| GET | `/api/v1/exports/alerts.json` | Same filters as `/alerts`; alerts + rule + notes + evidence | |

Writes marked ✔ return `403 DEMO_READ_ONLY` when `DEMO_READ_ONLY=true`.

## Examples

```bash
curl -F file=@sample_data/nginx/suspicious_access.log -F source_type=NGINX \
     http://localhost:8000/api/v1/datasets/upload
```

## Upload error codes

| Code | HTTP | Meaning |
|---|---|---|
| `UNSUPPORTED_FILE_TYPE` | 400 | Extension is not `.log` / `.txt` |
| `EMPTY_FILE` | 400 | No bytes, or only blank lines |
| `BINARY_FILE` | 400 | NUL bytes / high control-character ratio (e.g. `.gz`) |
| `INVALID_ENCODING` | 400 | Not valid UTF-8 |
| `FILE_TOO_LARGE` | 413 | Over `MAX_UPLOAD_SIZE_MB` |
| `TOO_MANY_LINES` | 413 | Over `MAX_LOG_LINES` |
| `UNRECOGNISED_FORMAT` | 422 | `AUTO` could not identify the format |
| `FORMAT_MISMATCH` | 422 | Content does not look like the chosen type; `details.suggested_source_type` |
| `RATE_LIMITED` | 429 | Too many uploads per minute |

Per-line parse errors (`NGINX_FORMAT_MISMATCH`, `INVALID_TIMESTAMP`, `INVALID_IP`, `INVALID_STATUS_CODE`, `SSH_FORMAT_MISMATCH`, `NOT_SSHD_LINE`, `UNSUPPORTED_SSH_MESSAGE`) do not fail the upload; they are stored in `import_errors`.
